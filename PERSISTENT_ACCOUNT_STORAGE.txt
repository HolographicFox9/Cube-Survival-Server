HOSTL PERMANENT ACCOUNT STORAGE

HOSTL stores account/player progression server-side in accounts.json. This includes Gold Cubits,
species cards, pet unlocks and stages, pet stat upgrades, starter purchases/preferences, themes,
achievements, materials, titles, codes, friends, and related permanent progression.

REQUIRED FOR PRODUCTION DURABILITY
A normal web-service filesystem can be replaced during deploys/restarts. Render Free web services
cannot attach persistent disks. Use a paid Render web-service compute plan with a disk (an optional
render-persistent-example.yaml is included), or move account storage to a durable database.

For a Render persistent disk:
1. Mount the disk at a path such as /var/data.
2. Set:
   HOSTL_DATA_DIR=/var/data/hostl
3. Keep HOSTL_SESSION_SECRET private and stable.
4. Redeploy and check /healthz.

When the path is truly backed by mounted durable storage, /healthz should report:
  accountStoragePersistent:true

Do not set HOSTL_DATA_DIR to a path that only looks persistent without actually mounting durable
storage. That would hide the warning while leaving accounts vulnerable to deploy loss.

SESSION + RECOVERY
HOSTL stores an HMAC-signed recovery snapshot in the player's browser. If accounts.json is missing,
signing in with the same Google account on that browser can restore the signed snapshot. The browser
cannot edit the snapshot without invalidating its signature.

This is a recovery safety net, not a replacement for durable server storage. Cross-device recovery
and reliable production accounts still require a persistent disk/database.
